# 论坛设计方向：小黑盒式校园电脑社区

2026-11-03，状态：设计提案；用户已指定深入参照小黑盒，先明确设计基调、页面结构与组件、交互细节，再进入页面实现。论坛为首个落地模块，其余页面按[模块化流程](frontend-polish-workflow.md)逐步推广。

## 1. 设计基调

**目标感受：专业、直接、有同好氛围。** 用户进入后能迅速找到值得阅读的帖子，看到真实的人和讨论，并自然参与求助或分享。

设计语言以小黑盒的兴趣社区方向为主参照，电脑医院保留自己的身份、五栏结构和双角色业务。配色、尺寸和具体行为采用下列项目规范。

| 维度 | 拟定规范 | 页面效果 |
| --- | --- | --- |
| 视觉重量 | 黑白灰为主体，低饱和黄只用于关键选中标记/发布动作，错误用语义红 | 帖子文字和图片成为主要视觉内容 |
| 背景 | 内容面 `#FFFFFF`，分区底 `#F5F6F7`，分隔线 `#E9EAED` | 连续阅读，层级清楚 |
| 文字 | 主文字 `#202126`，次文字 `#62666F`，辅助文字 `#717680` | 标题鲜明、正文清楚、元信息退后 |
| 强调 | 黄色 `#E8C547` 配深色文字；链接 `#315FAD` | 有辨识度，黄色不用于细小正文 |
| 字体 | HarmonyOS 系统字体；标题中粗、正文常规，中文阅读优先 | 原生、清晰、避免整页同样粗重 |
| 字号 | 频道 20–22fp；列表标题 17–18fp；详情标题 22–24fp；正文 16fp；元信息 12–13fp | 列表便于扫读，详情便于沉浸 |
| 密度 | 页面边距 16vp，块内间距以 4/8/12/16vp 为基础；帖子块间 8vp 分区 | 连续内容流，避免入口占满首屏 |
| 容器 | 内容块弱边界，图片 6–8vp 小圆角，底部面板 20vp 圆角 | 帖子自然连接，操作面板层级明确 |
| 图标 | 20–22vp 单色线性图标，44vp左右有效触控区域 | 清爽、动作可辨认 |
| 动效 | 按压 80–120ms，面板/状态切换 180–240ms；遵循减少动态效果设置 | 快、轻、反馈及时 |

社区氛围来自真实昵称、稳定的作者区域、清楚的讨论分类、自然的正文和图片，以及低门槛评论。无图求助帖与多图经验帖均是完整内容，版式根据实际内容变化。

沿用现有 `GENERAL / EXPERIENCE / QUESTION` 三类，显示「综合交流／经验分享／问题求助」。分类为空支持全部帖子，列表按现有服务端创建时间倒序呈现。

当前契约包含帖子/评论作者 `id/displayName`、图片、时间和评论数，没有头像 URL、公开作者主页、用户等级、关注、点赞、收藏、阅读数、热度或推荐排序。作者使用本项目默认头像；不展示上述缺失动作、计数或身份标记。帖子评论与内部备案评论继续独立。

## 2. 页面结构与组件

### 2.1 论坛信息流：先看到内容

从上到下：

```text
活动   论坛〔选中〕                    搜索  发布
全部   综合交流   经验分享   问题求助
────────────────────────────────────────
默认头像  昵称                         时间 · 更多
帖子标题：最多两行
正文摘要：最多两行，和标题重复时省略
实际图片：按单图／双图／三图布局
分类                                      评论数
────────────── 8vp 浅灰分区 ──────────────
下一条真实帖子……
────────────────────────────────────────
首页     活动     服务/工作台     选购     我的
```

- **频道栏**：活动/论坛各一个标题层级，当前频道字重提高并有短强调标记。删除重复「校园论坛」大标题。搜索图标打开论坛搜索模式，首屏以内容为主。
- **分类栏**：固定四项短分类，当前项深色字配轻量选中标记；保留全部入口，避免默认隐藏其他类别内容。
- **帖子块**：满宽白色内容面，靠内边距、细分隔与灰色分区区分；减少嵌套卡片和大阴影。作者行不跳转未提供的公开主页。
- **图文节奏**：无图帖紧凑；单图为有限高度封面，列表使用裁切、详情查看完整图；两图并排；三图及以上显示三张缩略图，超过三张标记真实总数。图片失败有固定占位和重试，保持块高稳定。
- **帖子动作**：点标题/正文进入详情；点缩略图进入同帖图片浏览；评论入口直达详情评论区域。更多只列服务端允许且已实现的操作。
- **发布入口**：频道栏右侧黄色图标按钮，清楚标注可访问名称。模拟器审查中右下悬浮按钮遮挡帖子评论入口，因此调整到频道栏。
- **首屏节奏**：以约 390vp 宽的基准视口看，头部与分类控制在约 100–120vp；常见文字帖能在首屏看到多条内容的开头。有图帖依据真实图片占高，保持标题可扫读。

组件落点：`ActivityPage` 负责活动/论坛频道壳；`ForumFeed` 负责分类、查询、列表和分页；需要复用时抽取论坛专用头部、帖子块、作者行和反馈组件。业务服务与 DTO继续复用现有实现。

### 2.2 搜索：范围明确，返回恢复

```text
返回    搜索论坛帖子……             取消/清空
全部   综合交流   经验分享   问题求助
真实搜索结果／无结果／失败重试
```

搜索只查论坛标题与正文，键盘提交后请求服务端，输入时不逐字触发请求。保留已应用关键词与当前输入的区分；清空后恢复当前分类。返回关闭搜索模式，并恢复搜索前列表位置；请求失败显示恢复动作，已有结果继续保留。

搜索模式先在频道内管理状态，不为 A 扩展全局搜索业务。搜索激活时焦点进入输入框，页面仍使用同一套分类和帖子块。

### 2.3 帖子详情：阅读为主，评论顺手

```text
返回                  帖子                   更多
分类 · 标题
默认头像  作者昵称                    发布时间
正文：清楚的段落、行距
图片：完整比例、点击浏览
────────────────────────────────────────
评论（真实数量）
默认头像  昵称                           时间
          评论正文                 授权操作
……分页评论……
────────────────────────────────────────
写下你的想法……                     评论入口/数量
```

- 正文 16fp、约 25–28vp 行高，段间 12–16vp；图片与相邻段落留 12vp，尊重原始图片顺序。
- 评论按当前接口的时间顺序显示，不添加「最热」排序或楼中楼。作者身份仅在与帖子作者 ID相等时标「作者」。
- 底部输入是主要操作；点击后扩展为输入区与发送按钮。评论数入口滚动到评论区，不额外加重复蓝色按钮。
- 删除放在更多/评论操作菜单，按 `actions.canDelete` 显示；危险操作使用明确文字和二次确认。

### 2.4 发布：轻编辑器

```text
关闭                  发布帖子               发布
选择分类：综合交流 / 经验分享 / 问题求助
标题……
分享经验或描述问题……
已选图片预览、删除、添加
────────────────────────────────────────
相册入口                             当前字数
```

标题、正文采用直接编辑区域，减少逐字段大卡片。分类靠前；字数/九图限制在接近限制或选择图片时呈现。发送前显示实际本地图片预览，上传中显示当前进度；失败图片带重试入口。

离开有改动的编辑器时提供「继续编辑／放弃」；发布请求在途或帖子已创建但上传未完成时，保留当前创建/上传身份，明确当前进度，按已有幂等与离开保护处理。跨重启本机草稿保存单列为后续增强，不作为现有功能。

### 2.5 我的帖子：延续公共信息流

复用帖子块、状态与分页行为，入口在「我的」。默认只展示本人真实帖子；删除操作按服务端 actions提供。返回恢复位置，发布/删除后同步公共列表和本人列表。首批不新增草稿箱或内容统计面板。

## 3. 交互细节

| 场景 | 确定的行为 |
| --- | --- |
| 频道切换 | 保留论坛分类/搜索/滚动位置；活动状态独立。频道横向手势不与整 App五栏横滑争抢，首批采用点击切换 |
| 分类切换 | 回到该分类顶部并请求第一页；显示轻量加载，取消旧结果覆盖；不会以旧类别内容冒充新类别 |
| 下拉刷新 | 顶部刷新真实列表；成功更新内容，失败保留旧列表并提示。轻量提示完成后收起，不跳动整个页面 |
| 分页 | 接近末尾请求下一页，保留手动「加载更多/重试」出口；同一页不并发重复请求。使用稳定帖子 ID并更新真实计数 |
| 返回列表 | 恢复分类、已应用查询和滚动锚点；同步变更帖，不因一次评论让整页回顶 |
| 点击评论 | 已登录进入详情评论区并可聚焦输入；游客先看到真实详情，写评论时按现有登录续接规则处理 |
| 键盘与返回 | 系统返回先收起键盘，再退出页面；页头返回退出当前页面。输入内容丢弃按编辑器规则提示 |
| 图片浏览 | 黑色阅读背景、左右切换、真实序号、缩放；退出回原帖原位置；图片资源继续走既有权限/URL通道 |
| 发送评论 | 提交中防重复；成功插入服务器返回评论、更新真实计数并清空输入；失败保留正文与原幂等键，原位重试 |
| 删除 | 菜单→确认→服务端成功→移除并同步计数；失败原位提示；帖子已删除/无权访问时收起旧正文并提供返回 |
| 发布与上传 | 一次发布意图只建一帖；已建帖后只续传剩余图片；失败状态不显示完成，成功后到真实详情 |
| 加载 | 初次加载用轻量骨架；分页只在尾部显示。加载中可按既有业务规则返回，离开后的迟到回调不改变新页面 |
| 空态 | 「还没有帖子，来分享第一条经验」／「没有找到相关帖子」，各配发布或清空筛选的真实动作 |
| 错误 | 显示用户能理解的结果和重试操作；错误码/服务器路径写入验证资料，不作为社区正文 |
| 触感/动效 | 按压颜色或透明度反馈；内容不弹跳入场；图片加载保留尺寸；减少动态效果开启后关闭额外过渡 |

## 4. 推广到其他模块的方式

论坛先确立字体、图标、分隔、选中态、面板与反馈语言；首页、服务/工作台、选购、我的逐模块继承这些规则，同时保留各自的任务结构。

五栏顺序及服务端角色分流保持现有业务基线。全局导航的最终视觉方向为轻量实底、清楚的图标/文字选中态；现有悬浮玻璃底栏的替换在独立导航工作块处理，届时验证全部五栏与减少动态效果。A 不扩散修改其他主页面。

其他模块开工时重新检查原「我的华为」参考和本提案的关系，优先采用用户此次指定的小黑盒设计语言；原参考图继续提供业务布局素材。主页主视觉、交易卡片与服务设备卡分别做模块方案，不机械套用帖子版式。

## 5. A/B/C 落地与设计验收

- **A 信息流**：频道/分类/搜索、作者行、三种图文密度、发布入口、加载/空态/错误与分页。
- **B 详情**：正文/图片、评论区、键盘输入、删除、返回锚点和计数同步。
- **C 创作**：轻编辑器、相册预览、上传恢复、离开确认、我的帖子。

每块按现有流程做本地视觉、操作、代码审查，再提交 #91 复审。视觉审查使用同状态参考/改前/改后；页面操作使用真实接口与课程样本，并记录每页未覆盖状态。

体验验收观察四点：首屏能否迅速读到帖子；无图/单图/多图是否形成自然节奏；阅读→评论→返回能否保持上下文；作者与讨论是否比容器、说明和装饰更突出。
