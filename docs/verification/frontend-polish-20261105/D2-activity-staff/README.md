## 实际检查

- 真实成员 API：创建带“现场界面验收样本”标识的活动和两条合成报名，截止报名后进入看板。样本创建流程见 [脚本](prepare-staff-fixture.cjs)；脚本使用进程环境提供凭据。
- 模拟器：标记出勤、取消出勤、重新出勤；对 Alpha 签到入队、撤回排队并再次签到。现场处理后服务端返回不能取消出勤的原因，界面显示该原因。
- 查看与隐藏合成联系号码；接待 Alpha 并进入真实备案草稿，返回后用“继续填写备案”恢复该草稿。通过系统相册选择仓库已有截图，填写验收内容和结果后提交，状态为待审核。
- Beta 再次走签到、接待、草稿与提交。提交前看板显示草稿，提交后返回显示待审核；最终包的两条已接待卡片均显示待审核，并从 Beta 卡片打开对应备案。两条验收草稿均已提交，不再阻塞成员继续接待。
- 客户账号请求成员看板返回 HTTP 403；没有变更后端权限规则。
- HAP 构建并安装成功，活动与登录相关测试 41 项通过，测试文件 ESLint 通过。摘要见 [version.json](version.json)、[构建日志](build.log)、[测试日志](tests.log)。设备为 Pura 90、API 24、1320 × 2856，浅色主题；API 指向本机隔离课设库 `pchospital_exp_forum_ui_20261103`。

## 本地审查

看板刷新失败时清除旧看板，避免继续显示失效操作；失败和恢复通过页面方法测试。修复列表以旧数据复用导致备案提交后仍显示草稿的问题，模拟器中复现并通过 Beta 草稿→待审核操作复核。待填写备案改为独立卡片，标题换行后仍可进入原草稿。

现场看板网络故障的模拟器注入、较大字号、管理模式及实体手机待验证；活动管理编辑与报名管理页面留待独立模块。用户可见的照片来自仓库已有截图，验收数据保留在隔离课设库中。
