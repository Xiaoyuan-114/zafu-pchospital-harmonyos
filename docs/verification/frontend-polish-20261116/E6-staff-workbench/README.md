首屏保留电脑医院自身的报修、备案、活动和知识语义。常用工作采用双列卡片，摘要改为本人备案状态、维修贡献和近期备案三段；知识入口收在后段，避免首屏出现过长说明。

## 改动

- `ServicePage.ets`：工作人员常用工作前置。普通工作人员的“本人维修备案”直达本人列表，可继续新建草稿；入口仍按服务端返回的权限生成。管理员的六个入口组成三行，典型案例库可直达；普通工作人员仍可从知识与帮助区进入案例库。
- `WorkbenchSummary.ets`：读取 `/api/v1/member/dashboard`，展示真实队列、维修贡献和近期备案。统计按双列排列；学期数据未配置时显示“待配置”。请求刷新保留旧内容，迟到响应不覆盖新请求；网络失败在摘要区显示重试。无成员档案的管理员显示对应说明。
- 游客服务入口及客户原有流程保持可用。

## 实际验证

环境：Pura 90 模拟器，1320 × 2856；本机课设后端 `http://127.0.0.1:13080`，独立实验库 `pchospital_exp_forum_ui_20261103`；员工账号 `100002`、管理员账号 `100003`。基线已合入 `main 9d75b04`。本模块没有修改后端或数据库结构。

| 操作 | 结果 |
| --- | --- |
| HAP `assembleHap`、安装与启动 | 构建成功，模拟器安装并启动；[构建记录](build.log) |
| 员工工作台首屏与滚动 | 四个常用工作卡片为双列；下滚可见本人备案状态、维修贡献、近期备案及知识入口；[首屏](staff-top.jpeg)、[中段](staff-middle.jpeg)、[下段](staff-bottom.jpeg) |
| 真实工作摘要 | `/api/v1/member/dashboard` 显示草稿 0、审核中 2、已退回 0；累计已审核和本月已审核为 0，本学期显示“待配置”；近期有 2 条审核中备案 |
| 备案入口与返回 | “本人维修备案”进入本人备案列表，看到 2 条记录和“新建备案”；“已审核备案库”进入空态“当前范围暂无维修备案”；近期备案可打开真实详情，返回工作台 |
| 报修与案例入口 | “报修工作台”进入真实待处理报修列表；典型案例入口进入案例库；均可返回工作台 |
| 摘要刷新、失败与恢复 | 服务可用时刷新实际统计；停止本机后端后摘要显示“工作摘要加载失败，请检查连接”和“重试”，见[错误截图](summary-error.jpeg)；重新启动后端并点击“重试”，恢复 0/2/0 及原有入口，见[恢复截图](summary-recovered.jpeg) |
| 游客服务与维修指南 | 游客四个服务卡片保持原顺序；指南请求失败时显示页内错误及重试，左上返回服务页；[游客页](service-guest.jpeg)、[指南错误页](guide-error.jpeg) |
| 管理员权限组合 | `100003` 显示备案审核、成员活动、案例库和管理入口；案例库为空态“暂无案例”，管理入口进入活动管理。该账号无成员档案时工作摘要显示“当前账号没有成员档案，维修摘要不可用”；[前后对照](admin-final.jpeg) |
