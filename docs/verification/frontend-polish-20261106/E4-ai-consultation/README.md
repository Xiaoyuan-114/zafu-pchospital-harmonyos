问诊页增加更清晰的入口文案和发送按钮；输入框按接口上限约束，聚焦时调整键盘避让，失焦或离开后恢复设置。页头返回和系统返回均对已有对话或输入进行退出确认；清空前要求确认。离开、清空后作废迟到结果；重试较早的问题不强制滚动到末尾。模型未配置时展示面向用户的真实服务状态，原问题可重试。

## 实际操作

- Pura 90 模拟器（API 24，1320 × 2856）：从首页进入问诊，选择示例问题；系统返回弹出确认，再按系统返回关闭弹窗，输入保留。页头返回也弹出同一确认；确认退出后回首页，再次进入是新对话。
- 客户发送问题后本机接口返回 `AI_NOT_CONFIGURED`，界面显示服务尚未配置。点击重试，原问题保持一条；取消清空保留对话，确认清空回到空态。
- 连续发送三个问题时列表滚动到最新一条，[截图](multiple-errors.jpeg)来自加入退出确认前的构建；最终包已复核输入、错误、清空及返回。
- 游客从首页选择问诊，登录工作人员后续接问诊；工作人员发送问题得到相同的真实服务状态。完成后恢复客户验收账号。
- 本地独立课设库和关键词索引用于接口核对：客户检索“开机黑屏”得到 3 条公开结果，读取第一条来源成功，服务端返回公开文档和固定版本原文链接。

最终 HAP 构建并安装成功，SHA-256 `B0480310709CF7932A8BF37BFD2CC78715298D5541834704DB5BCD3A28910E7A`，见[构建日志](build.log)。相关测试 31 项和新增测试文件 ESLint 通过，见[测试日志](tests.log)；状态测试覆盖确认取消、退出、迟到回复、旧消息重试和键盘设置恢复。

本地服务没有配置回答模型，生成回答、澄清、资料不足、引用卡进入详情及从来源返回对话待模型服务恢复后验证；键盘实际弹出时的布局和实体手机待验证。来源检索接口已独立核对，未替代完整问诊链路。
