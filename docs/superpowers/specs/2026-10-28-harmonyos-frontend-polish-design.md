# 鸿蒙电脑医院前端全面打磨设计

日期：2026-10-28

分支：`feat/issue-85-forum-polish-20261028`

接续：上游草稿 PR #91；基点为当时最新 `main 7041b84` + 草稿提交 `5bf15c2`

关联：Refs #85、Refs #42

## 1. 目标与基线

以“我的华为”16 张参考图为视觉和交互依据，提升五个主页面及主要子页面的还原度与连续操作完成度。保留双角色权限、真实接口、维修/备案区别、购物/报修区别、带来源 AI 问答与典型案例回流，不用演示数据、静态结果或可点击空壳冒充完成。

冲突需求以 `README.md`、`docs/current-goals.md` 为准：客户五栏为 **首页｜活动｜服务｜选购｜我的**；工作人员第三栏为工作台；知识在服务/工作台内，不恢复旧知识 Tab。旧 Web 全量迁移及无关 AI 扩展不在本轮范围。

## 2. 实施路径取舍

采用 **接续 PR #91、按业务模块小步交付**：

- 保留草稿论坛后端三表、接口、权限和幂等边界，新增独立 `features/forum/` 原生页面与服务。
- 复用 `core/auth`、`core/network`、`core/ui` 及已有业务组件，按实际差异修改页面，不重写全仓 UI。
- 首页、服务/工作台、选购、我的先修跨页入口和参考图差异；活动/论坛完成纵向真实闭环；最后修主链子页和跨模块一致性。

未采用另起纯 UI 分支：会丢失论坛后端并需要额外集成。未采用全面重写：会破坏已验证业务、权限和返回规则。

## 4. 公共 UI、导航与反馈

- 保留 260ms 原生 Tab 滑动、液态玻璃底栏及 `reduceMotion`；子页统一由 `NavPathStack` 管理，页内返回与系统返回语义一致。
- 以 `Theme.ets`、`ReferencePage.ets`、`ReferenceDetail.ets`、`StatePanel.ets` 为公共基础，按参考图收敛必要字号、间距、圆角、图标和图片比例。只抽真正复用的结构，避免为统一而重建业务组件。
- 首屏加载、局部刷新、分页、空数据、无搜索结果、接口错误、网络错误和提交失败分开呈现。已有内容时局部刷新不整页闪白，失败不清掉可保留的真实内容；提交防连点，错误保留可重试上下文。
- 图片只来自真实接口或明确的项目插画，插画标注非现场照片/诊断结果。缺图、解码失败与重试可见，不以设计图冒充实物。
- 表单检查最大长度、字段错误、提交中禁用、键盘避让与焦点返回；敏感写操作有确认和完成反馈。

## 5. 论坛设计与数据流

### 5.1 客户端契约

新增 `ForumContract.ets`、`ForumService.ets`，严格映射 `backend/docs/forum-api.md`：分类 `GENERAL / EXPERIENCE / QUESTION`，帖子/评论/图片 DTO、分页和服务端 `actions`。调用 `/api/v1/forum/posts`、`/me/posts`、`/posts/{id}`、`/comments`、`/images`，不在客户端推定管理员或作者权限。

### 5.2 页面与登录续接

- 活动 Tab 内设“活动 / 论坛”，论坛频道提供分类和关键词搜索；`ForumPostDetailPage`、`ForumComposePage`、`MyForumPostsPage` 为子路由，并接我的页面。
- 公开列表/详情游客可读。游客点发帖/评论时保留当前草稿页或详情上下文并打开登录页，成功后回到原页面继续，不能发送 `authorId` 或写死身份。
- 发布分创建帖子与图片上传：一次发布意图生成 `createRequestKey`，创建成功后保存 ID；上传失败只重试剩余图片，不重复建帖。每张图片使用独立 `uploadKey`，发送前绑定当前选择，结果未知重试不重新生成。
- 评论同样复用一次提交意图的幂等键；明确成功后清空。发送中禁止重复操作，迟到响应不导航到已离开的页面或替换新账号状态。
- 删除需确认，按服务端 `actions` 显示；删除后列表、详情、评论数和我的帖子一致刷新，404 不继续显示旧正文。

### 5.3 状态与边界

标题 120 字、正文 10000 字、评论 2000 字、搜索 60 字，每帖最多 9 图；首版不支持编辑帖子/评论、点赞、关注、私信、积分、公告 CMS、楼中楼或推荐算法。论坛内容不复用内部备案评论、附件或消息。

## 6. 关键业务修复原则

- 选购列表把 `q` 与 `category/page/pageSize` 一起传给现有商品接口，服务端负责完整数据集查询；请求代次防止旧关键词结果覆盖新输入，空结果显示真实无匹配状态。
- 既有 `PendingOrderStore`、库存乐观锁和订单快照不削弱。涉及写操作时沿用页面销毁/会话代次检查，避免迟到成功导航或错误退出新会话。
- 论坛也采用 `generation/disposed` 和会话归属检查；不把长请求期间简单禁用返回当成通用方案。确实不可中途离开的认证写请求保留既有拦截。
- 服务端始终是权限和状态判定来源；界面只根据真实身份、权限和 `actions` 控制入口，不扩大客户、工作人员、卖家、作者或管理员能力。

## 7. 实施模块与验证门

1. **公共证据与入口**：页面对照、路由/登录边界、公共 UI；五栏与角色导航实机通过。
2. **活动＋论坛纵向闭环**：游客浏览→登录续接→A 发帖/图片→B 查看/评论→A 我的帖子→作者/管理员删除；活动报名回归。每页截图和相关真实 HTTP/必要回归。
3. **首页、服务/工作台、我的**：参考图、双角色入口、我的帖子、知识与维修主链；受影响子页实机验证。
4. **选购与交易**：真实搜索与视觉打磨；买家下单/取消、卖家交付/取消、发布/编辑、订单状态；保留并复核幂等/权限。
5. **主链子页与一致性**：按实际发现修复知识、维修、个人、活动子页的返回、状态、键盘与反馈；不扩大无关审计。
6. **最终验证与 PR**：构建 HAP，逐页截图及参考映射，记录模拟器/API/真实库、未覆盖状态、共享部署和真机限制，更新原草稿 PR，保持开启供维护者审查，不自行合并。

每个模块先针对将修行为建立最小可复现检查，再实现；纯视觉差异以参考图和模拟器截图核验。异步/幂等等可测逻辑优先使用已有测试方式，不引入新测试框架。
